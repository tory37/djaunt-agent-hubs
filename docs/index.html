A live page for every long-running job.

djt-hub is a small local web server. Your agent writes the page as one React file, and it hot-reloads as the agent works. You watch it and click the gates.

The agent attaches with one command. Every click comes back to it as a line of JSON.

      The loop

      The agent writes the page. You decide. The agent acts.

      Every command prints JSON. The page is one file the agent edits. No server code, no build step.

      quick start
      $ djt-hub create release-42 --title "Release 4.2"
# the agent writes view_path: <Steps id="run" bind="steps" />
$ djt-hub patch release-42 --json '[{"path":"steps","value":[
    {"id":"build","label":"Build","status":"running"},
    {"id":"promote","label":"Promote","status":"waiting","gate":"Promote to prod?"}]}]'
$ djt-hub open release-42
$ djt-hub listen release-42     # attach; one JSON line per click
$ djt-hub patch release-42 steps.promote.status=running
$ djt-hub close release-42

      The kit

      Import a kit, or write your own JSX.

      Each component reads inline props, or binds to a path in the hub's JSON state. Patch the value and every open tab updates.

      Steps

      Runbook steps with status, live timers and approval gates.

      • builddone
      • migratedone
      • promotewaiting for you

      Checklist

      Items to tick. Each toggle is an event.

      Stats

      Big numbers with units and a tone: ok, warn, bad, info.

      Chart

      Line, area or bar. Time series or categories.

      Table

      Rows from state. Status columns render as badges.

      Log

      Lines from state, or live events filtered by prefix.

      Actions

      Buttons. Dangerous ones ask for a second click.

      Form

      Fields that submit their values as one event.

      Grid + Panel

      A gapless 12-column bento. Panels take a width.

      Anything else

      It is React. useHub() gives you state, emit and patch.

      Events

      Every click is an event with a seq.

      Listen for all of them while you work, or wait for one. Pass a seq to replay what you missed.

      • gate.approvegate.reject
      • actionbutton press
      • form.submitvalues by field
      • checklist.toggleitem and done
      • hub.emit(type, payload)Your own JSX can send any type.
      • emit <hub> <type> [json]The agent can add events too, for a live log.
      djt-hub listen release-42
      {
  "seq": 41,
  "hub": "release-42",
  "source": "user",
  "type": "gate.approve",
  "payload": { "block": "run", "step": "promote", "note": "go" },
  "ts": "2026-10-16T15:42:07Z"
}

      Attach

      No agent, no clicks.

      The page only acts while an agent listens. Nothing spins up on its own, and no click lands where nobody is listening.

      tag on to a hub
      # stream every click, under a background monitor
$ djt-hub listen release-42
# or block on one gate
$ djt-hub wait release-42 --match step=promote --timeout 1h
# is anyone listening?
$ djt-hub show release-42      # "attached": true
      • 01
        The page shows itA chip in the header reads agent attached or no agent.
      • 02
        Read-only when aloneWith no agent, controls lock and a banner shows the listen command to copy.
      • 03
        A short graceThe hub stays attached 60s after the last listener, so a click between two wait calls still lands.

      The daemon never acts on a click by itself. A click asks; the attached agent acts, then updates the page.

      Install

      Install it, run it under launchd, open a page.

      Needs Bun. Binds to 127.0.0.1 only and keeps hubs as plain files in ~/.local/share/djt-hub/.
